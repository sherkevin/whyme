## 5. 风险与建议

1. **9.19 是 §30 最后一公里**——不修则「回答保存为文档」全链路看不到结果；演示时必须靠脚本侧（`chrome-mcp-smoke.ps1`）证明 worker 链路活。
2. **多 demo 账号污染**：实测时浏览器自动切到工程师 2 的 `demo_final` 而不是 Agent 4 的 `demo`。建议 §10.7 cron 重置 + Production seed 时只保留 `demo@mydow.example`。
3. **8771 vs 8000 端口共存**：当前两个 uvicorn 并行（工程师 2 在 8771 / Agent 4 在 8000），Chrome MCP 自动绑 8771。后续投资人 demo 必须只起一个端口避免歧义。
