## 2. 详细需求

### 2.1 B-03A：SMTP 邮件服务配置

#### 2.1.1 需求描述
建立系统级邮件发送能力，为后续验证码、通知等功能提供基础邮件服务。

#### 2.1.2 功能清单

| 功能项 | 说明 |
|--------|------|
| SMTP 配置管理 | 支持 host、port、user、pass、from 等参数配置 |
| 环境变量集成 | 配置项可通过环境变量注入，支持不同环境（dev/staging/prod） |
| 配置加载机制 | 应用启动时自动加载并校验配置完整性 |
| Mailer 模块封装 | 统一邮件发送接口，支持 HTML 格式和纯文本格式 |
| 失败重试机制 | 发送失败时自动重试（最小可用版本） |
| 错误日志记录 | 详细记录发送失败原因，便于排查 |

#### 2.1.3 技术规范

```yaml
# 配置结构示例
smtp:
  host: ${SMTP_HOST}
  port: ${SMTP_PORT:587}
  user: ${SMTP_USER}
  pass: ${SMTP_PASS}
  from: ${SMTP_FROM:noreply@example.com}
  tls: true
```

#### 2.1.4 接口设计（内部模块）

```typescript
// Mailer 模块接口
interface Mailer {
  // 发送纯文本邮件
  sendText(to: string, subject: string, content: string): Promise<Result>;

  // 发送 HTML 邮件
  sendHtml(to: string, subject: string, html: string): Promise<Result>;
}

interface Result {
  success: boolean;
  messageId?: string;
  error?: string;
  retryCount: number;
}
```

#### 2.1.5 验收标准

| 验收项 | 验收标准 | 验证方式 |
|--------|----------|----------|
| 功能验收 | 在预发/本地环境可成功发送一封测试邮件 | 手动测试 |
| 错误处理 | 配置缺失/错误时返回可读错误信息并有日志记录 | 单元测试 |
| 格式支持 | 支持 HTML 和纯文本两种邮件格式 | 单元测试 |
| 日志记录 | 发送成功/失败均有结构化日志输出 | 代码审查 |

#### 2.1.6 依赖与风险

| 依赖项 | 说明 |
|--------|------|
| B-01 | 基础项目框架搭建完成 |
| B-42 | 日志模块已集成 |

### 2.2 B-03B：发送验证码接口

#### 2.2.1 需求描述
提供用户邮箱验证码发送能力，用于登录验证、邮箱绑定等场景。

#### 2.2.2 功能清单

| 功能项 | 说明 |
|--------|------|
| 验证码生成 | 生成 6 位数字随机验证码 |
| 验证码存储 | 以 email 为 key 存储到 Redis，设置 TTL 过期时间 |
| 邮件发送 | 调用 Mailer 模块发送验证码邮件 |
| 频率控制 | 同邮箱/同 IP 限制发送频率，防止滥用 |
| 频控复用 | 复用 B-40 的频控基础设施 |

#### 2.2.3 API 规范

**接口**：`POST /auth/send-code`

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| email | string | 是 | 接收验证码的邮箱地址 |
| type | string | 否 | 验证码类型：login/bind/reset（默认 login） |

**响应示例**：

```json
// 成功响应 (200)
{
  "code": "SUCCESS",
  "message": "验证码已发送",
  "data": {
    "expires_in": 300  // 有效期 5 分钟（秒）
  }
}

// 频控触发 (429)
{
  "code": "RATE_LIMITED",
  "message": "发送过于频繁，请 60 秒后重试",
  "retry_after": 60
}

// 参数错误 (400)
{
  "code": "INVALID_EMAIL",
  "message": "邮箱格式不正确"
}
```

#### 2.2.4 Redis Key 设计

| Key 模式 | 示例 | TTL | 说明 |
|----------|------|-----|------|
| 验证码存储 | `verify_code:{email}:{type}` | 300s | 验证码内容 |
| 邮箱频控 | `rate_limit:email:{email}` | 60s | 同邮箱发送间隔 |
| IP 频控 | `rate_limit:ip:{ip}` | 60s | 同 IP 发送间隔 |

#### 2.2.5 邮件模板

**主题**：`【XX平台】您的验证码是：{code}`

**内容**：

```
您好，

您的验证码是：123456

该验证码 5 分钟内有效，请勿泄露给他人。

如非本人操作，请忽略此邮件。
```

#### 2.2.6 验收标准

| 验收项 | 验收标准 | 验证方式 |
|--------|----------|----------|
| 发送成功 | 调用接口返回成功且邮箱收到验证码 | 集成测试 |
| 存储验证 | 验证码写入 Redis 且到期自动失效 | 单元测试 |
| 频控生效 | 重复请求触发频控，返回明确错误码 | 单元测试 |
| 格式校验 | 非法邮箱格式返回明确错误 | 单元测试 |

#### 2.2.7 依赖与风险

| 依赖项 | 说明 |
|--------|------|
| B-03A | SMTP 邮件服务已配置完成 |
| B-02 | Redis 连接已建立 |
| B-40 | 频控模块已提供复用接口 |

### 2.3 B-03C：验证码校验接口

#### 2.3.1 需求描述
提供验证码校验能力，支持登录流程集成，确保验证码一次性使用且防暴力破解。

#### 2.3.2 功能清单

| 功能项 | 说明 |
|--------|------|
| 验证码校验 | 验证用户提交的验证码是否正确 |
| 一次性消费 | 校验通过后立即删除 Redis key，防止重复使用 |
| 失败计数 | 同 key 记录失败次数，超过阈值锁定 |
| 错误分类 | 区分 expired（过期）/ invalid（错误）/ too_many_attempts（锁定） |
| 统一错误码 | 标准化错误码输出，便于前端处理 |

#### 2.3.3 API 规范

**方案 A：独立校验接口（推荐）**

**接口**：`POST /auth/verify-code`

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| email | string | 是 | 邮箱地址 |
| code | string | 是 | 用户输入的验证码 |
| type | string | 否 | 验证码类型（默认 login） |

**响应示例**：

```json
// 校验通过 (200)
{
  "code": "SUCCESS",
  "message": "验证通过",
  "data": {
    "token": "temp_token_xxx"  // 可选：返回临时 token 用于下一步登录
  }
}

// 验证码错误 (400)
{
  "code": "INVALID_CODE",
  "message": "验证码错误，还剩 2 次机会"
}

// 验证码过期 (400)
{
  "code": "CODE_EXPIRED",
  "message": "验证码已过期，请重新获取"
}

// 尝试次数超限 (403)
{
  "code": "TOO_MANY_ATTEMPTS",
  "message": "验证失败次数过多，请 30 分钟后重试"
}
```

**方案 B：集成登录接口**

**接口**：`POST /auth/login-with-code`

**请求参数**：email + code，直接完成登录

#### 2.3.4 安全策略

| 策略 | 配置 | 说明 |
|--------|------|------|
| 最大尝试次数 | 5 次 | 超过则锁定该邮箱验证码功能 |
| 锁定时间 | 30 分钟 | 锁定期间禁止该邮箱的验证尝试 |
| 失败计数 TTL | 30 分钟 | 与锁定时间保持一致 |

#### 2.3.5 Redis Key 设计（补充）

| Key 模式 | 示例 | TTL | 说明 |
|----------|------|-----|------|
| 失败计数 | `verify_attempts:{email}:{type}` | 1800s | 记录验证失败次数 |
| 锁定标记 | `verify_locked:{email}:{type}` | 1800s | 锁定期间的标记 |

#### 2.3.6 状态流转图

```
[验证码已发送]
      ↓
[等待验证] ──(正确code)──→ [验证通过] → [删除验证码]
      │
      ├──(错误code)──→ [失败计数+1] ──(<5次)──→ [等待验证]
      │                                   │
      │                                   └──(≥5次)──→ [锁定30分钟]
      │
      └──(code过期)──→ [返回过期错误]
```

#### 2.3.7 验收标准

| 验收项 | 验收标准 | 验证方式 |
|--------|----------|----------|
| 正确验证 | 输入正确 code 可通过且验证码被消费（删除） | 单元测试 |
| 错误验证 | 输入错误 code 返回 invalid 且不通过 | 单元测试 |
| 过期处理 | 过期验证码返回 expired 错误 | 单元测试 |
| 防暴力破解 | 多次错误后触发锁定，返回 too_many_attempts | 单元测试 |
| 一次性使用 | 验证通过后再次使用返回 invalid | 单元测试 |

|--------|------|
| B-03B | 发送验证码接口已完成 |
| B-03 | 用户模块已提供用户信息查询 |

## 3. 非功能性需求

| 类别 | 要求 |
